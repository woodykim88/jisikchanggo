# Astryx 디자인 규칙 핵심 요약

- 출처: https://github.com/meta/astryx (Meta 사내에서 8년 쓰던 디자인 시스템, 1만 3천 개 앱에 쓰였다. MIT 라이선스, 2026-11 베타)
- 원문: `원문/design`(디자인 원칙 16개), `원문/families`(컴포넌트군 규칙 7개), `원문/tokens.stylex.ts`(실제 수치). 복사한 시점은 `원문/커밋.txt`에 있다.
- 이 라이브러리는 React 19와 StyleX 전용이다. 우리 앱(SwiftUI·Kotlin·Blogger 테마)에 라이브러리를 직접 넣지는 않는다. 아래 **원칙과 수치만** 가져다 쓴다.
- 쓰는 때: 앱 화면 설계, Impeccable 점검, 계산기 사이트 UI 수정, 앱 심사 전 점검.

## 1. 바로 쓰는 수치

| 항목 | 값 | 쓰는 곳 |
|---|---|---|
| 짧은 반응(누름·토글·호버) | 130 / **175** / 230ms | 버튼 피드백, 체크 |
| 등장·퇴장 | 310 / **410** / 550ms | 시트, 모달, 카드 등장 |
| 큰 이동·연속 동작 | 730 / **975** / 1300ms | 화면 전환, 진행 연출 |
| 닫힘(퇴장) | 짧은 반응과 같음(175ms) | 닫는 건 여는 것보다 빠르게 |
| 기본 감속 곡선 | `cubic-bezier(0.24, 1, 0.4, 1)` | 들어오는 것, 상태 변화 |
| 퇴장 곡선 | `cubic-bezier(0.3, 0, 0.6, 0.6)` | 나가는 것(가속) |
| 모서리 반경 | 안쪽 4 / 요소 8 / 컨테이너 12 / 페이지·시트 28 / 알약 9999 | 겹친 모서리는 바깥 = 안쪽 + 여백(동심원) |
| 간격 단위 | 4px 배수(2·4·6·8·12·16·20·24·…·48) | |
| 모바일 본문 글자 | 최소 16px | iOS 입력칸은 16px 미만이면 확대됨 |

SwiftUI 변환 예: `.animation(.timingCurve(0.24, 1, 0.4, 1, duration: 0.41))`

## 2. 원칙 (우리 앱 기준으로 고른 것)

**움직임** (`design/motion.md`, `reduced-motion.md`)
- 움직임에는 뜻이 있어야 한다(반응·연속성·등장·퇴장·위치 변화). 장식용 애니메이션은 쓰지 않는다.
- 무게가 시간을 정한다. 작은 피드백은 빠르게, 큰 등장은 느리게 한다.
- 튕김·고무줄 같은 탄성 대신 부드러운 감속으로 끝낸다(브랜드 성격상 등장에서만 살짝 넘침 허용).
- '동작 줄이기' 설정을 켜면 이동을 없앤다. 터치 화면은 교차 페이드로, 마우스 화면은 즉시 바꾼다. 뜻은 그대로 전달한다.
- 호버로 뜨는 것(툴팁 등)은 짧게 기다린 뒤 띄우고, 벗어날 때 깜빡이지 않게 한다.

**상태 표시** (`system-states.md`, `user-states.md`, `families/buttons.md`)
- 로딩이 레이아웃을 흔들면 안 된다. 버튼이 로딩 중이어도 크기와 문구 자리는 그대로 둔다.
- 상태의 뜻은 색 없이도 전달돼야 한다(아이콘·문구 병행).
- 오래 남는 문제일수록, 급할수록 더 눈에 띄게 한다. 토스트는 잠깐, 배너는 오래 보인다.
- 비활성은 '아무 반응 없음'이다. 비활성 이유를 볼 수 있게 한다.
- 선택 상태가 호버나 누름보다 우선한다.

**간격·위계** (`spatial-hierarchy.md`, `template-composition.md`, `typography-hierarchy.md`)
- 가까움이 관계를 말한다. 묶음 수준이 올라갈수록 간격을 키운다.
- 테두리·박스보다 여백으로 먼저 묶는다(space precedes containment).
- 이웃한 글자 역할(제목·부제·본문)은 확실히 구분돼야 한다.
- 화면 배치만 보고도 그 화면의 목적이 읽혀야 한다.

**색·강조·깊이** (`color-emphasis.md`, `elevation-hierarchy.md`)
- 강조색은 아껴 쓴다. 화면당 주요 행동은 하나다.
- 글자색과 배경색은 한 번에 함께 정한다(대비).
- 그림자는 조용하게 쓴다. 테두리와 그림자 중 한 가지 언어만 앞세운다.
- 포커스 링은 높이(그림자) 표현이 아니다.

**조작 크기** (`control-rhythm.md`, `iconography.md`)
- 보이는 크기와 누르는 영역은 별개다. 작아 보여도 터치 영역은 44pt 이상으로 둔다.
- 한 줄에 섞인 버튼·입력칸은 높이와 기준선을 맞춘다.
- 아이콘은 외곽선형이 기본이고, 크기는 역할을 따른다.

**입력칸** (`families/input-fields.md`)
- 검색칸은 키보드에 '검색' 키를 띄우고 자동 교정을 끈다.
- 키보드를 띄우는 요소는 키보드 위에 보이게 한다.
- 잘못된 입력은 너무 일찍 표시하지 않고, 조용히 버리지도 않는다.

**AI 상태** (`agentic-states.md`, 초안)
- AI가 진행 중·대기·확인 중·결과 제시인지 알려 줄 때 새 표시 언어를 만들지 말고 기존 로딩·상태 표시를 재사용한다. 숨은 추론 과정은 노출하지 않는다. CalNote 요약 진행 표시에 해당한다.

## 3. 안 가져온 것과 이유
- `@astryxdesign/core` 라이브러리와 `astryx` CLI: React 웹 전용이다. 지금 React 웹앱이 없어서(Remotion·my-vrew만 있음) 설치하지 않았다. 새 React 웹 화면을 만들게 되면 `npm i -g @astryxdesign/cli` 후 `astryx build "<화면 목적>"`로 템플릿부터 시작한다.
- `packages/native`(SwiftUI 바인딩): 실험 단계(canary)이고 제품용이 아니라고 저장소가 직접 밝혔다. 필요하면 원 저장소의 `packages/native/apple/Templates/`만 참고한다.
- 문서를 압축해 토큰을 줄이는 규칙(`.claude/skills/dense-compression-protocol.md`): Astryx 컴포넌트 문서 전용이라 그대로 쓸 데가 없다. 다만 "개수는 1:1로 지키고 관사·군더더기 동사만 뺀다"는 방식은 스킬 문서를 줄일 때 참고할 만하다.
